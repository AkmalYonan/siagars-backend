# Keputusan implementasi 0.1

- **Deployment aktif (24 Okt 2026):** produksi demo memakai adapter serverless Vercel pada `https://siagars-backend.vercel.app`; `cmd/api`, Dockerfile, dan Compose tetap menjadi jalur deployment alternatif. Smoke test read-only untuk health, readiness, daftar RS, layanan, dan OpenAPI lulus. Login, CSRF, mutasi operator, serta QA browser terhadap produksi belum dijalankan. Risiko Atlas allowlist luas, dokumentasi publik, dan limiter per-instance dicatat di `deploy/VERCEL.md`.
- **Temuan kontrak terbuka:** nilai pencarian `q` yang diawali karakter `$` masih ditolak oleh validasi query. Frontend tidak boleh bergantung pada pencarian tersebut sampai kontrak atau implementasinya diputuskan; lihat `API_FRONTEND.md`.
- Acuan utama adalah PRD/AGENTS backend baseline 23 Oktober 2026. Ide AI discovery 500 RS dari percakapan awal belum masuk kontrak v0.1 ini; dapat menjadi tahap berikutnya setelah direktori pilot dan data tervalidasi.
- Backend versi berjalan berada di `backend/`; dokumentasi dalam repository ini harus mengikuti implementasi tersebut.
- Tidak memakai router/framework tambahan: net/http cukup untuk route v0.1. MongoDB melalui driver resmi go.mongodb.org/mongo-driver/v2.
- Dependency: mongo-driver v2.9.2 dan x/crypto v0.57.0, dikunci di go.mod/go.sum.
- MongoDB Atlas adalah penyimpanan utama; tidak ada fallback in-memory yang menyamarkan readiness. Pencarian memakai query pushdown MongoDB untuk filter, pencarian teks, urutan nama, hitungan, dan paginasi. Sort jarak/kecocokan masih diselesaikan di Go setelah filter database.
- Kontrak OpenAPI tersedia dalam sintaks JSON yang valid sebagai YAML. Semua endpoint baseline tercantum. Enum, nullability dan version harus dijaga bersama frontend.
- Body error unknown field400, query unknown422, body limit413, batas page1.000.000 diputuskan eksplisit dalam kontrak.
- Update facility/referral memperlakukan operator sebagai demo: provenance simulation, tidak otomatis verified. Facility response dibaca ulang setelah commit, sehingga dapat merefleksikan versi lebih baru jika ada update berikutnya; client wajib memakai version dari response/refetch.
- API tidak melakukan migrasi otomatis. Manage migrate memakai advisory lock transaksi + checksum. Tidak ada down/reset otomatis.
- Akun operator dibuat secara eksplisit dari env, tidak di-seed dengan password bawaan. Session dan token tracking disimpan hash; token CSRF deterministik dari session random dan hanya hash tersimpan.
- Limiter per instance cukup untuk demo. Trusted forwarding header sudah didukung melalui `TRUSTED_PROXIES`; rate limit bersama untuk deployment multi-instance belum tersedia.
- SATUSEHAT fase MSI Sandbox (lihat entri 23 Okt di bawah). Tidak ada clinical resource, write FHIR atau production.
- 23 Okt 2026: penyimpanan dipindah dari PostgreSQL ke MongoDB Atlas atas permintaan tim. Kontrak HTTP, DTO, enum, dan fixture tidak berubah. PRD sudah direvisi untuk MongoDB Atlas.
- Model dokumen: layanan dan bed di-embed dalam dokumen hospitals sehingga update per item atomik (positional `$` + `$elemMatch` pada version). Penugasan RS operator di-embed sebagai `operators.hospital_ids`. Nama kota/provinsi/layanan di-join di Go dari koleksi master.
- Integritas: `$jsonSchema` + `$expr` validator (enum, range, null vs 0, available<=total, lat/lng berpasangan, slug/kategori unik per RS, email normalized) dan unique index. MongoDB tidak punya FK: keberadaan RS dicek aplikasi saat membuat operator; seed konsisten dengan master wilayah. Tidak ada endpoint penghapusan, jadi tidak ada cascade.
- Status+history+audit dan update fasilitas+audit memakai transaksi multi-dokumen (butuh replica set; Atlas memenuhi). Write conflict di-retry driver lalu callback mendeteksi version berubah dan mengembalikan 409.
- Migration berupa file JSON bernomor (extended JSON) berisi perintah create/createIndexes, dicatat di schema_migrations dengan checksum. DDL MongoDB tidak transaksional; setiap perintah aman diulang (create jatuh ke collMod). Lock lewat dokumen `locks` dengan kedaluwarsa 5 menit.
- Seed memakai upsert `$setOnInsert` dan `$push` bersyarat dalam satu transaksi, sehingga tidak menimpa pembaruan operator. Session kedaluwarsa dihapus TTL index 1 hari setelah expires_at.
- 23 Okt 2026, SATUSEHAT MSI Sandbox: sinkronisasi read-only via `manage sync-satusehat`, bukan saat startup API dan bukan endpoint. Tidak ada base URL production di kode; config menolak SATUSEHAT_ENV=production. SATUSEHAT_ORGANIZATION_ID belum dipakai karena MSI tidak memerlukannya.
- DTO MSI defensif: dokumentasi resmi mengetik kode wilayah, koordinat dan expires_in berbeda antara skema (number) dan contoh (string/null), jadi decoder menerima string/number/null. Objek bertingkat boleh null. Kode wilayah MSI (provinsi 2 digit, kab/kota 4 digit, mis. 3171) disimpan apa adanya dan tidak dikonversi ke format seed (31.71); akibatnya filter city_code untuk RS sandbox memakai kode MSI.
- Koordinat 0,0 dianggap unknown (placeholder umum, di luar Indonesia). Ini kebijakan defensif, bukan perilaku terdokumentasi MSI.
- Importer: unordered BulkWrite per halaman agar satu record yang ditolak validator tidak menghalangi lainnya; penolakan dihitung failed dan membuat command exit non-zero. `source_hash` (SHA-256 field ter-normalisasi) membedakan updated vs unchanged. Tidak memakai transaksi per halaman: setiap upsert idempoten dan halaman yang sudah tertulis adalah last-known-good yang sah.
- Migration 002 mengganti validator hospitals lewat collMod (validator 001 dinyatakan ulang utuh + field sumber baru) dan menambah aturan: data selain curated/simulation wajib punya external_id dan source_namespace. Dokumen lama tetap valid; tidak ada backfill. Pembacaan publik memakai filter `source_active != false` sehingga dokumen tanpa field tetap tampil.
- Catatan awal tentang pencarian seluruh RS di memory sudah digantikan oleh keputusan paket B di bawah. `sort=distance|match` tetap memuat hasil yang telah difilter karena perhitungannya dilakukan di Go.
- 23 Okt 2026, sync Jabodetabek: cakupan wilayah memakai parameter resmi `kode_kabkota` per kab/kota (SATUSEHAT_KABKOTA), bukan filter lokal atas hasil nasional, plus pemeriksaan ulang city_code per record. Data live mengonfirmasi `kabkota.kode` MSI mengikuti kode Kemendagri tanpa titik (3171 = Jakarta Pusat, 3174 = Jakarta Selatan), sedangkan seed sintetis memakai kode bertitik dengan label fiktif; keduanya hidup berdampingan sebagai region terpisah.
- 23 Okt 2026, pemisahan data simulasi: `GET /hospitals` mendapat parameter `dataset=real|simulation|all` (default real = semua data_origin selain simulation) dan `meta.dataset`. Perubahan aditif pada kontrak, tetapi default mengubah isi daftar: 30 RS fiktif tidak lagi muncul tanpa `dataset=simulation|all`. Pemisahan hanya pada tampilan daftar; dokumen tetap satu koleksi `hospitals` dan detail `/hospitals/{id}` serta tujuan lookup SR-DEMO-001 tetap dapat memuat RS simulasi. Frontend yang menampilkan skenario demo harus mengirim `dataset=simulation` (atau all). Contoh `services=nicu,icu` dihapus dari OpenAPI karena Swagger UI mengirimnya otomatis dan menyaring seluruh data nyata (yang belum punya layanan).
- 24 Okt 2026, paket B (hardening backend). **Pushdown pencarian:** `GET /hospitals` memakai `repository.SearchHospitals` (dipakai handler lewat interface opsional `Searcher`; store lain tetap jatuh ke `Hospitals`+`service.Filter`). Filter dasar menjadi `$match` terstruktur: `source_active != false`, dataset (`data_origin`), `province_code`, `city_code`, `bpjs` (null tidak pernah cocok), `services` AND lewat `$elemMatch` per slug dengan status available/limited, dan `has_available_beds` lewat `$elemMatch` bed (`available > 0`, bukan simulasi, `source_updated_at` dalam (now-1 jam, now]) yang identik dengan `domain.Freshness`=fresh. `q` memakai `$lookup` nama kota/provinsi dan `$indexOfCP` atas "nama kota provinsi" seperti haystack lama (termasuk kecocokan lintas batas kata); teks pengguna hanya menjadi nilai string BSON, bukan regex/operator. Urutan `name` (default) disort, dihitung dan dipaginasi di database (`$toLower`+`_id`, top-k) sehingga hanya satu halaman dipindahkan. `sort=distance|match` bergantung pada hitungan per RS, jadi himpunan yang sudah tersaring dimuat dan diurutkan oleh `service.Filter` (perilaku identik). Detail RS dan tujuan lookup memakai `Repository.Hospital` (satu dokumen), bukan memuat semua RS. Kontrak HTTP tidak berubah; satu kalimat klarifikasi ditambahkan ke deskripsi OpenAPI. Batasan yang diketahui: `$toLower` MongoDB hanya melipat huruf ASCII, sedangkan Go melipat Unicode; nama dengan huruf kapital non-ASCII bisa berbeda untuk `q` dan urutan nama. Tidak berdampak pada data sekarang (nama Indonesia ASCII), tetapi perlu field nama ternormalisasi bila kelak ada.
- **Migration 003** (`003_search_indexes.json`, 001/002 tidak diubah): index `hospitals_dataset_region_idx` (data_origin, province_code, city_code), `hospitals_dataset_city_idx` (data_origin, city_code) dan `hospitals_services_idx` (services.slug, services.status). Pengurutan nama memakai kunci `$toLower` yang dihitung, jadi tidak memakai index `hospitals_name_idx`; sort memakai optimisasi top-k (memori setara skip+limit dokumen) dan `allowDiskUse`.
- **Bukti ekuivalensi:** `tests/integration/search_pushdown_test.go` membangun 300 RS sintetis (campuran origin, bpjs null/true/false, status layanan, bed fresh/aging/batas tepat 1 jam, 10 dokumen nonaktif) di database tes sementara dan membandingkan JSON hasil `SearchHospitals` dengan `service.Filter(Hospitals())` untuk 160 kueri acak (semua sort, dataset, q, paginasi). Lulus (68 kueri tidak kosong). Test unit builder filter ada di `internal/repository/search_test.go`.
- **Trusted proxy:** env `TRUSTED_PROXIES` (daftar CIDR/IP dipisah koma, default kosong, nilai tidak valid membuat startup gagal). `X-Forwarded-For` hanya dibaca bila peer TCP langsung ada di daftar; daftar dibaca dari kanan dan hop pertama yang bukan proxy tepercaya menjadi identitas klien untuk rate limit login/lookup; header tak terparse atau semua hop tepercaya jatuh ke alamat peer. Header tidak pernah dipakai untuk hal lain. Limiter tetap per instance (in-memory); rate limit multi-instance belum dikerjakan.
- **Pengukuran baca lokal (bukan SLA):** (a) `go test ./internal/service -bench Filter -benchmem` (CPU Ryzen 5 5600, Windows, Go 1.27, 200 iterasi, hanya filter in-memory tanpa database): n=30 14-37 µs/op; n=500 0,26-0,69 ms/op; n=5000 3,1-10,1 ms/op (3 pola kueri; angka dan alokasi lengkap dari `-benchmem`). (b) `SEARCH_BENCH=1 go test ./tests/integration -run TestSearchLatency -v` pada database tes sementara di Atlas (jaringan WAN dari mesin pengembang, 3.000 RS sintetis + 30 seed, 40 kali per kasus): jalur lama (`Hospitals`+`Filter`) p50 ≈ 233-247 ms, p95 ≈ 251-274 ms untuk semua kasus; jalur pushdown p50/p95: default halaman 1 88/104 ms, province+services 81/89 ms, sort=match 2 layanan 83/95 ms, has_available_beds+q 126/135 ms, sort=distance 187/207 ms, q=sehat 229/245 ms. Satu kali jalan, satu mesin; sebagian besar waktu adalah round trip jaringan ke Atlas sehingga angka tidak mewakili produksi. `q` paling lambat karena `$lookup` pada semua dokumen yang lolos `$match`; `sort=distance` tetap memindahkan himpunan tersaring. Tidak ada klaim SLA.
- **Kode wilayah MSI vs seed:** MSI memakai kode Kemendagri tanpa titik (provinsi `31`, kab/kota `3171`), seed sintetis memakai `31.71`; provinsi (`31`,`32`,`36`) sama, kab/kota berbeda format. Kedua kumpulan hidup sebagai region terpisah, jadi `city_code=3171` hanya menemukan RS sandbox dan `city_code=31.71` hanya RS seed. Label juga bertabrakan: seed menamai `31.71` "Jakarta Selatan" sedangkan `3171` Kemendagri adalah Jakarta Pusat. **Usulan (tidak diterapkan):** jadikan format tanpa titik kanonik; (1) migration baru yang menambah `regions.aliases` (mis. `31.71` untuk `3171`) dan menamai ulang region seed fiktif agar tidak bentrok, (2) `RegionExists` dan filter `city_code` menerima alias lalu menormalkannya ke kode kanonik, (3) seed berpindah ke kode kanonik dengan backfill `city_code` yang idempoten. Tidak diimplementasikan karena menerima `31.71` sebagai `3171` mengubah hasil filter yang ada (RS seed "Jakarta Selatan" akan tercampur dengan RS nyata Jakarta Pusat) dan memengaruhi seed/fixture, sehingga menyentuh kontrak dan berkas di luar kepemilikan paket ini; perlu keputusan tim dan koordinasi frontend.
- 24 Okt 2026, paket G (fitur Should: compare, sort, bed). **Compare:** endpoint baru `GET /hospitals/compare?ids=a,b,c` (aditif; `/hospitals` dan `/hospitals/{id}` tidak berubah). Dipilih daripada parameter `ids` pada `GET /hospitals` karena daftar punya semantik paginasi/filter/`meta.total` dan `ids` akan memaksa aturan khusus (tolak semua filter lain, `total`, `dataset`) di endpoint yang sudah punya kontrak; path sendiri memberi skema respons sendiri (array 2-3 item, tanpa paginasi) dan sebagian besar logika (UUID, pencarian satu dokumen) memakai ulang `hospitalByID`. Aturan: 2 sampai 3 ID unik berformat UUID lowercase, selain itu 422 (ids hilang, <2, >3, duplikat, bukan UUID/kapital/spasi/elemen kosong; parameter lain, kosong atau berulang juga 422). Keputusan ID tidak ditemukan atau `source_active=false`: **404 semua-atau-tidak-sama-sekali** dengan pesan `Rumah sakit tidak ditemukan: <id yang hilang>` (hanya ID yang hilang disebut). Alasan: respons parsial bisa dibaca frontend sebagai perbandingan lengkap; ID bukan data sensitif. Urutan `data` sama dengan urutan `ids`. Setiap item adalah DTO detail yang sama dengan `/hospitals/{id}` (layanan/bed dengan provenance dan version per item; freshness dihitung ulang saat request); unknown tetap `null`, bed 0 tetap 0. Seperti detail, RS simulasi dapat dibandingkan dan campuran real+simulasi diperbolehkan (parameter `dataset` tidak berlaku). `meta` berisi `as_of` dan `count`. Implementasi memanggil `hospitalByID` per ID (maks 3 baca satu-dokumen) tanpa method repository baru. Routing: `GET /hospitals/compare` lebih spesifik daripada `/hospitals/{id}`; fallback 405 khusus tidak didaftarkan karena konflik dengan `GET /hospitals/{id}` pada ServeMux, sehingga metode lain tetap menghasilkan 405 `Allow: GET` lewat fallback `{id}`. UUID adalah lowercase sehingga tidak ada RS bernama `compare`.
- **Verifikasi sort dan bed (paket G):** `sort=distance` (terdekat dulu, koordinat unknown terakhir dengan `distance_km` null bukan 0, tie nama lalu ID), `sort=match` (status layanan yang diminta available +10/limited +5, freshness fresh +3/aging +1, simulasi tanpa bonus, lalu jarak bila ada lat/lng, nama, ID) dan `has_available_beds=true` (available>0, fresh = `source_updated_at` dalam (now-1 jam, now], bukan simulasi; null dan 0 tidak cocok) sudah sesuai PRD dan kini diuji eksplisit per batas (`internal/service/compare_test.go`); ekuivalensi jalur database sudah dijaga `tests/integration/search_pushdown_test.go`. Tidak ditemukan bug. Catatan semantik yang bukan bug: `has_available_beds=false` diterima tetapi sama dengan tidak memfilter (tertulis di OpenAPI); skor match menjumlahkan semua layanan yang diminta (jika `services` kosong, semua layanan RS dihitung) dan `sort=match` tanpa filter `services` karenanya mengurutkan menurut kelengkapan layanan, bukan kualitas klinis.
